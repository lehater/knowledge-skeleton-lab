# Природа референта Knowledge: `kind`

**Нормативный контракт.** Значение `kind` — необязательная *основная* природа предметного референта, не предметная область, уровень таксономии или роль в конкретной связи. `type: knowledge` остаётся единым. Выбирай значение по определению предмета и первоисточнику, не по названию файла, соседям или префиксу технологии. Если нельзя подтвердить выбранный референт — оставь `kind` пустым и уточни содержание.

## Выбор

1. Определи единый референт (модель, API-тип, конкретное программное средство, ресурс, исполняемая работа, записанный артефакт и т.д.). Не смешивай вещь, её представление, реализацию и запись о ней.
2. Проверь положительный и отрицательный тесты таблицы. Если подходят два класса, уточни референт, затем выбери наиболее специфичный для него.
3. Предметные области и обзорные темы выражаются `in_topic`, тематические уровни — запросами Scope; `topic` используется, когда **сам предмет Knowledge** — область рассмотрения.
4. Компонентность в конкретной системе, исполняемая роль, реализация и состав проверяются отдельными отношениями по `rules/relations.md`; не делай такие выводы только из `kind`.
5. У предмета могут быть другие истинные характеристики; `kind` фиксирует одну основную для навигации. Новые обязательные поля/фасеты не добавляются.

## Допустимые значения и границы

| kind | Определение и критерий выбора | Положительные примеры | Отрицательный тест и ближайший класс |
|---|---|---|---|
| `topic` | Именованная область рассмотрения либо обзор нескольких самостоятельных предметов и их взаимосвязи. Выбрать, когда предмет карточки — именно охват, а не одна из входящих вещей | Python/Java Concurrency; Python Functions and Iteration | Python-language и Python Execution Model не становятся topic от наличия дочерних заметок. В model нужна связная система представления предмета |
| `model` | Представление определённого предмета через выбранные понятия, отношения, состояния или семантические правила. Указать предмет и критерий/цель представления | Execution Model, JMM, жизненный цикл контейнера, модель слоёв sandbox | SLI — мера, SLO — цель; тематическое оглавление не модель. Нормативность источника сама не превращает model в specification |
| `principle` | Общее правило организации/проектирования, направляющее множество конкретных решений. Выбрать, когда предмет — предписание, как строить решение | Structured Concurrency; Data Abstraction при явно закреплённом проектном смысле; Least Privilege вне корпуса | Concurrency — property существующего исполнения; TaskGroup — program_construct; последовательность действий диагностики — method |
| `property` | Характеристика предмета/поведения, о которой можно утверждать наличие, отсутствие, степень или значение | Concurrency, Parallelism, Mutability, Binary Compatibility, Polymorphism и его виды | Scheduler — mechanism; SLI — metric измерения характеристики; правило ограничивать привилегии — principle |
| `constraint` | Предел или условие допустимости состояния/исполнения в выбранном контексте. Выбрать, когда предмет — граница, а не способ её применения | E2B Project Limits; Error Budget как допустимый расход; max_turns/stopping conditions | cgroup — mechanism enforcement, SLO — goal. Ограничение может одновременно стать requirement, если предметом является принятое обязательство |
| `requirement` | Принятое требуемое условие или способность предмета в определённом контексте. Выбрать по обязанности соответствовать, а не по наличию численного порога | Требование к времени ответа или аудиту в согласованном контракте; в корпусе 0 | Цель SLO без обязательства — goal; физический предел ресурса — constraint; документ со многими требованиями — specification |
| `goal` | Желаемый исход или целевое значение/диапазон характеристики на заданном горизонте | SLO | Измерение текущей доступности не цель; наличие цели не устанавливает SLA-обязательство |
| `metric` | Определённая количественная мера либо явно заданное семейство мер одной величины с границей измерения и правилом вычисления | SLI; GenAI token metrics; latency metrics | Сохранённый telemetry datapoint — данные, не определение меры. Four Golden Signals — модель выбора разнородных диагностических измерений |
| `practice` | Устойчивый способ организации инженерной работы с полезной ответственностью, допускающий несколько процедур/средств | Concurrent Programming, Context Engineering, Note-Taking, Harness Engineering | Конкретный incident response — process; Hypothesis-Driven Troubleshooting как процедура — method; принцип не является деятельностью |
| `method` | Воспроизводимый способ решения инженерной задачи с определёнными шагами/проверками и результатом, допускающий предметные суждения исполнителя | Hypothesis-Driven Troubleshooting, ReAct, калибровка grader, canary analysis | Сам факт диагностики — process/деятельность. Полностью вычислимые правила анализа — algorithm; абстрактная схема организации решения — solution_pattern |
| `algorithm` | Заданные вычислимые правила преобразования входа/состояния в результат, достаточные для машинного исполнения при указанных предпосылках | Java definite-assignment analysis и правила type inference; Quicksort вне корпуса | Общее назначение GC или scheduler ещё не конкретный алгоритм. Термина «механизм» недостаточно для восстановления шагов. Завершение/полноту алгоритма не обещать без источника |
| `process` | Тип разворачивающегося во времени исполнения деятельности/вычисления с событиями, состояниями и исходом | Trial, Single-Agent Loop, Incident Response, Thread как поток исполнения, Asynchronous Task как работа | API-handle Task/Thread — program_construct; журнал — artifact; модель состояний процесса — model. Не объявлять конкретный run подтипом процесса |
| `solution_pattern` | Переиспользуемая схема решения повторяемой проблемы в определяемом контексте с существенными компромиссами | JIT Context Retrieval; Initializer/Coding Agent | Java matching pattern — program_construct; Structured Concurrency здесь principle; observed pattern и anti-pattern автоматически не включаются |
| `mechanism` | Организация технического действия через правила работы/взаимодействия частей, обеспечивающая определённый эффект. Конкретный алгоритм может быть неизвестен или изменяем | GC, dispatch, backpressure, namespaces, compaction, replay | Descriptor object — program_construct, не сам lookup; Free Threading как возможность — property; ресурсный предел — constraint |
| `program_construct` | Формально определённый вид/элемент программного языка, runtime или API: тип, объявление, объектный протокол, операция или программное выражение | Python/Java Class, String, MemoryDataset, Scorer, Code/Frame/Traceback objects, Java module/package | Библиотека asyncio — software; общий Programming Interface — interface; descriptor сообщения MCP — data_structure. Один кодовый шрифт или CapitalCase не доказывает этот класс |
| `data_structure` | Организация данных/информации через элементы, поля и связи. Выбрать, когда предмет — представление записи, дерева, последовательности или графа, а не объявленный API-тип | OTel Span/LogRecord, LangSmith Run, AST как дерево, Tool Call/Result, MCP notification | Frame object как определённый runtime-тип — program_construct; факт происшествия — event; нормативная JSON Schema — specification, хотя сериализуется данными |
| `software` | Программное средство или документированное семейство средств с реализованными возможностями: библиотека, SDK, инструмент, framework, платформа, служба | CPython, asyncio, JDK, Collector, Langfuse, BrowserGym | Python/Java — language; Volume — resource; MCP — protocol; конкретный класс API — program_construct. Здесь не требуется тождество обязанностей всех видов software |
| `language` | Язык программирования, моделирования или запросов, определяемый допустимыми формами и их значением | Python, Java; SQL/TLA+ вне корпуса | CPython — software implementation; JVM в текущем референте — model абстрактной машины; набор правил обмена — protocol |
| `component` | Архитектурно определённая ответственная единица системы с границей взаимодействия, рассматриваемая как тип подсистемы, а не конкретный API-символ/пакет | Agent Harness, Collector Receiver/Processor/Exporter, Pipeline, Asynchronous Runtime | Библиотека не обязана получать этот kind из-за part_of; Executor API-class — program_construct. Для универсального запроса «все части» служит отношение, не этот класс |
| `resource` | Выделяемая, подключаемая или управляемая операционная среда/ёмкость/хранилище/соединение, используемые вычислением и имеющие собственный срок жизни | E2B/Modal Sandbox, Docker/E2B/Modal Volume, Python venv, Secret, stream connection | OTel Resource — data_structure описания; SDK-handle — program_construct; ограничение объёма — constraint, не сам ресурс |
| `interface` | Граница взаимодействия, задаваемая доступными операциями и обязательствами сторон, независимо от конкретного языка и реализации | Programming Interface, BrowserGym Action Space, Modal Filesystem API, Store contract, procfs environ interface | Java interface как языковой тип — program_construct; запись описания Tool — data_structure; документ/схема определения интерфейса — specification |
| `protocol` | Правила взаимодействия участников обмена: сообщения, допустимые операции, порядок и семантика взаимодействий | MCP, OTLP | Документ спецификации — specification; отдельное сообщение — data_structure; продукт, реализующий протокол, — software. Protocol не является видом implementing SDK |
| `specification` | Предписанное определение правил соответствия/поведения/структуры данных. Предмет — нормативное содержание контракта, схемы или правила, а не носитель или реализация | JSON Schema input/output, GenAI Semantic Conventions, Object equality/hash contract, scoring policy, alert rule | Сам интерфейс/протокол не автоматически документ спецификации; настроенный YAML-файл — artifact; отдельное принятое требование — requirement |
| `artifact` | Информационный/исполняемый продукт деятельности, рассматриваемый как сохраняемый или передаваемый предмет: файл, журнал, snapshot, конфигурация, демонстрационный код | Agent Progress File, Sandbox Snapshot, Alertmanager config, Class File, Registry Definition | Любая заметка является файлом, но её референт не обязательно artifact. EvalLog API-класс и AST-структура имеют более специфическую природу. Роль «выход» не достаточна |
| `role` | Определяемый в контексте набор ответственностей/полномочий, являющийся самостоятельным предметом | Initializer Agent Role, Coding Agent Role | Агент-носитель — другой референт; роль source как исполнителя в executes не требует kind role у самого source |
| `event` | Тип значимого происшествия/изменения, различаемый с отдельным вхождением и записью о нём | Domain Event, событие завершения задачи вне корпуса; в корпусе 0 | OTel Event/Span Event и MCP notification сейчас описывают записи/сообщения, не сами происшествия. Trial с длительностью — process |
| `problem` | Определённый класс трудности, нежелательной ситуации или задачи, требующей решения | Context Rot; задача сортировки/вычислительная проблема вне корпуса | Риск, отказ, требование и ограничение не являются синонимами problem; защитная мера — другое понятие |

## Семантика и отношения

- `kind` не является формальным `rdf:type` и не образует закрытую иерархию классов мира.
- Разные `kind` на концах отношения могут быть правильными: `specializes` требует видовое отношение, `realizes` — реализацию конкретной абстракции; см. `rules/relations.md`.
- Не заменяй `in_topic` на более «сильное» отношение только из-за типов узлов. Отношение требует самостоятельного источника и проверки его смысла.
- Не создавай новые Knowledge, значения `kind` и UUID ради заполнения словаря. Подтверждённые разночтения сначала устраняй в определении референта.
