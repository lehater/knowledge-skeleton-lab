# Канонические направленные отношения v1

Рёбра записываются в Knowledge-источнике в формате `source → predicate → target`. Цель — существующий Knowledge. Обратные связи вычисляются; рёбра необязательны.

| Предикат | Смысл |
| --- | --- |
| `in_topic` | source рассматривается в теме target, по выбранному источнику; не означает наследование или композицию |
| `broader` | тема source уже темы target |
| `specializes` | source — частный вид target (`is-a`) |
| `part_of` | source — составная часть целого target |
| `realizes` | source — конкретная реализация абстракции target |
| `schedules` | source планирует исполнение target |
| `executes` | source выполняет / обеспечивает выполнение target |
| `manages` | source управляет жизненным циклом target |

## Применение

1. Если материал действительно выражает связь, добавь её в исходный Knowledge и укажи материал в `sources` этого Knowledge. **Не нужен отдельный реестр обоснований рёбер.**
2. Выбирай предикат по его смыслу: авторская рубрикация, `is-a`, `part-whole`, реализация и функция — разные отношения. Оглавление само по себе не доказывает `part_of` или `specializes`.
3. Если отношения не следует из источника или его тип непонятен, оставь Knowledge без этой связи.
4. Не создавай дубли тройки, самоссылки, записанные обратные рёбра и циклы `broader`, `specializes`, `part_of`.
5. Compass/K-Plex/Canvas визуализируют имеющиеся связи, не устанавливают новых фактов.

## Существующая карта

В ETCLOVG из [Agent Harness Engineering: A Survey, Figure 4](https://picrew.github.io/LLM-Harness/main.pdf#page=8) зафиксированы 42 `in_topic` (7 направлений и 35 подразделов). Это тематическая группировка авторов, а не `part_of` или `specializes`.

Словарь из восьми предикатов остаётся закрытым. Добавление предиката — отдельное изменение схемы и валидатора; обычный Discovery его не требует.
