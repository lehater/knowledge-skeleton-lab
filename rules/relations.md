# Канонический словарь направленных отношений v1

Любая связь записана в **исходном** Knowledge как `source → predicate → target`; цель — существующий Knowledge. Рёбра опциональны.

| Предикат | Семантический контракт | Пример / отличие |
| --- | --- | --- |
| `in_topic` | source рассматривается в тематической области target по указанному источнику | `Single-Agent Inner Loop → Lifecycle & Orchestration` по Figure 4; **не** является подтипом или частью |
| `broader` | предметная **тема** source уже, чем тема target | только при явном обосновании тематической иерархии; **не** автоматически из оглавления |
| `specializes` | source — частный **вид** target (is-a) | принципиально отличается от `in_topic` |
| `part_of` | source — составная **часть** целого target (part-whole) | принципиально отличается от `broader` |
| `realizes` | source — конкретная реализация абстракции/принципа target | не означает простое применение/использование |
| `schedules` | source планирует выполнение target | функциональное отношение |
| `executes` | source обеспечивает выполнение target | функциональное отношение |
| `manages` | source управляет жизненным циклом target | функциональное отношение |

## Состояние словаря

Все восемь предикатов **допустимы контрактом**. Это не означает, что **каждое существующее ребро** уже подтверждено.

- Доказанная по первоисточнику текущая структура: **42 `in_topic`** ETCLOVG (7 направлений, 35 подразделов) на основании Figure 4 одного обзора. Это **авторская рубрикация**, не универсальная онтология Harness Engineering.
- Рёбра `broader` и остальные, перенесённые из старых экспериментов, остаются **кандидатами** до отдельного relation audit.
- `categories` — удалённое поле старой двухтипной модели. `in_topic` — новое утверждение с определённым смыслом; **механическое преобразование старого `categories` само по себе не подтверждает фактический смысл**.
- `broader` **не устарел** как предикат; устаревшими могут быть только необоснованные употребления.

## Правила построения и ревью

1. **Node gate:** оба конца ребра должны существовать, иметь достаточное доказательство названия и быть правильно отождествлены. Для очистки старых данных сначала завершается node audit.
2. **Edge gate:** явно зафиксируй источник конкретного утверждения и различи классификацию автора, типизацию, композицию, реализацию и функциональную ответственность.
3. Дубли `source + predicate + target`, самоссылки и записанные обратные/выводимые рёбра запрещены. `broader`, `specializes`, `part_of` не должны образовывать циклов.
4. При `INSUFFICIENT_EVIDENCE` спорное ребро не утверждается; существующее требует решения в последующей итерации, а не автоматической замены `broader` на `in_topic`.
5. Семантика связи определяется полем, а не Compass-позицией в K-Plex и не линией Canvas. Графическое представление не создаёт новых канонических фактов.
6. Новый предикат вводится только через явное изменение этого словаря, schema, tests и review; не через случайное поле YAML.
