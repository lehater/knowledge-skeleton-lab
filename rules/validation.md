# Проверка целостности Knowledge Graph

## Обязательная техническая проверка

Из корня репозитория:

```bash
node tools/validate.mjs
node --test tools/validate.test.mjs
git diff --check
```

Валидатор проверяет YAML, UUIDv7 и уникальность ID, обязательные поля, синтаксис URL, `name`/H1, `lifecycle`, допустимые предикаты, ссылки и существование целей, повторы и циклы `broader`/`specializes`/`part_of`. Поля `categories` и файлы `type: category` запрещены.

## Предметная корректность

В обычном Discovery достаточно в момент написания прочитать компетентный источник, корректно перенести его содержание и сохранить URL в `sources`. Для связей достаточно, чтобы их смысл соответствовал источнику и [relations.md](relations.md).

Никакие дополнительные `source_verified`/semantic/GUI gates, реестры evidence или независимые ревью не являются обязательным условием наполнения графа. При конкретной ошибке корректируй соответствующий Knowledge или отношение.

**Ограничение:** успешный валидатор доказывает техническую целостность, но не истинность содержимого. Проверка применимости источника остаётся частью самого извлечения знания.

Исторические статусы аудитов в `reports/` не нужно продолжать при новых итерациях.
