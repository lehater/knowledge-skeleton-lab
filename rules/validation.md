# Четыре независимых уровня проверки

| Gate | Ответственность | Исполнение | Что **не** доказывает |
| --- | --- | --- | --- |
| **Static** | YAML, UUIDv7, обязательные поля, URL-синтаксис, допустимые предикаты, формат wikilink, существование целей, циклы, дубли | `node tools/validate.mjs`, `node --test tools/validate.test.mjs`, CI | Не доказывает, что URL содержит название |
| **Source** | Существует ли названный референт в прочитанном источнике; соответствует ли термин референту | Evidence-реестр, независимые ссылки и локации в источниках | Не доказывает корректность рёбер |
| **Semantic** | Соответствует ли `source → predicate → target` смыслу предиката и основанию | Независимое предметное ревью рёбер | Не заменяет синтаксическую проверку |
| **GUI** | Видны ли нужные узлы, стрелки, подписи, переходы и фильтры в K-Plex | Ручная проверка Obsidian; сохранённые наблюдения | Не доказывает предметную истинность |

## Техническая проверка

Из корня репозитория:

```bash
node tools/validate.mjs
node --test tools/validate.test.mjs
git diff --check
```

Валидатор проверяет **структуру** текущего `vault/`: `knowledge`/UUIDv7/уникальность, `sources`/URL-формат, `name`/H1, `lifecycle`/тело, `review_status`, уникальные поля/рёбра, `in_topic` и другие разрешённые ссылки, циклы `broader`/`specializes`/`part_of`. Legacy `type: category` и `categories` запрещены.

**Source/semantic не автоматизируются проверкой URL-синтаксиса.** Не объявлять `PASS` на всех уровнях по одному успешному CI. Для node audit использовать [rules/discovery.md](discovery.md); для отношения — [rules/relations.md](relations.md).

## Границы Stage 0

На этапе очистки Harness изменения ограничиваются документацией/настройками/проверками, а **не** Knowledge. Отсутствие изменений предметных файлов должно быть подтверждено diff. Следующий этап — Source evidence audit каждого узла.
