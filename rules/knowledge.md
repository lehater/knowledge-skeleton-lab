# Работа с Knowledge

Применяется при создании и изменении `vault/knowledge/entries/`; совместно с [schema.md](schema.md), [taxonomy.md](taxonomy.md) и [relations.md](relations.md). Общие ограничения описаны в корневом [AGENTS.md](../AGENTS.md).

- Создавай предметный Knowledge только при устойчивом референте, самостоятельной смысловой границе и пользе отдельной навигации.
- Файл — `vault/knowledge/entries/<slug>.md`; физические каталоги не означают предметную принадлежность.
- Для `lifecycle: skeleton` тело содержит **только H1**, совпадающий с `name`.
- `categories` ссылается на самые конкретные обоснованные категории; предков по `broader` вычисляют, а не сохраняют повторно.
- `specializes`, `part_of`, `realizes` — только предметно подтверждённые отношения; не подменяй один предикат другим.
- Перед созданием проверь дубликаты по `name`, `aliases` и смыслу. При неоднозначности вынеси варианты и обоснования в `reports/`.
- Новый UUIDv7 можно получить из корня репозитория: `node tools/new-id.mjs`; проверяй уникальность.
- Все YAML-wikilinks внутри Vault используют пути вида `[[taxonomy/categories/example]]` без `vault/`.
