# Knowledge: идентичность, доказательство, решение

## Идентичность

Узел обозначает названный **референт** (предмет, механизм, практику, технологию или тематическую сущность). Сначала ищи совпадения среди `name`, `aliases` и референтов остальных Knowledge. Общее имя не доказывает тождества; похожие названия не доказывают различия. Не дели составные названия автоматически.

Создавай UUIDv7 один раз через `node tools/new-id.mjs`. При исправлении источника/имени сохраняй ID, пока референт тот же. `review_status: proposed` означает, что принятие ещё открыто.

## Evidence gate — применяется к **каждому** узлу

1. Прочитай первоисточник, указанный в `sources`; проверь, что **именно это название** либо однозначный эквивалент реально присутствует в источнике и обозначает данный референт.
2. Запиши `evidence_url` и точное место (**заголовок, раздел, страница или якорь**), сопоставление исходного имени и `name`/`aliases`.
3. Если источник не подтверждает: проверь другие авторитетные источники, но **не** переноси значение термина из другого контекста (пример риска: `Asynchronous Flow Control`).
4. Если есть доказательство — `verified`. Если поиск не завершён или значение неоднозначно — `unresolved`. Если после разумной проверки подтверждения заявленного референта нет — `unsupported`, с указанием просмотренных источников.
5. Регистрируй результат в отдельном evidence-реестре по формату [discovery.md](discovery.md); URL сам по себе не является доказательством.

## Решение по существующему узлу

- **verified:** сохранить узел и UUID; не повышать `review_status` без отдельного решения о принятии.
- **unresolved:** не маркировать доказанным; запросить дополнительную проверку, явно показать препятствие. Не удалять как будто ложный.
- **unsupported:** подготовить удаление с перечислением входящих/исходящих ссылок и зависимых представлений. Удалять **после фиксации доказательств и влияния**, в отдельном data PR. Не заменять неизвестный узел выдуманным названием.

**Изолированные узлы допустимы.** Обоснование существования узла не требует доказанной связи; relation audit начинается после node audit.
