# Knowledge: источник, идентичность, содержание

## Выбор источника

Для каждого знания выбирай наиболее подходящий доступный достоверный источник: отраслевой стандарт или официальную спецификацию, документацию разработчика, признанную первичную научную работу. Универсальной шкалы доверия не требуется: источник должен быть компетентен **именно в рассматриваемом вопросе**.

Прочитай конкретный материал и перенеси утверждение без расширения его смысла. Запиши URL в `sources` Knowledge. Отдельного журнала доказательств не требуется. Ссылку на недоступную или нерелевантную страницу нельзя использовать вместо чтения.

## Идентичность

Один Knowledge обозначает один референт. Перед созданием сравни смысл с существующими `name` и `aliases`; переиспользуй Knowledge и UUID при совпадении. Похожие названия сами по себе не доказывают ни совпадения, ни различия.

Для нового Knowledge создай UUIDv7 командой `node tools/new-id.mjs`; в существующем UUID не меняй при обновлении названия или текста, если сущность та же.

## Наполнение

- Используй `lifecycle: enriched` для небольшого точного утверждения или определения под H1; `sources` содержит URL материала.
- `lifecycle: skeleton` допустим для именованной заготовки, тело — только H1.
- `review_status: proposed` при создании — совместимость со схемой, **не** обязательная очередь на независимое ревью.
- Поля `aliases` и `kind` необязательны. Не создавай дубли для разных точек зрения на тот же референт.

При сомнении в содержании вернись к источнику; если неясность остаётся, не утверждай спорный факт. Узлы без рёбер допустимы.
