# Discovery графа — ограничения

Процедура повторяемого создания Knowledge описана в [Discovery Skill](../.agents/skills/knowledge-graph-discovery/SKILL.md). Здесь — предметные ограничения, действующие независимо от исполнителя.

- Новые Knowledge должны обозначать самостоятельные, отличимые по смыслу референты. Не создавать узел на каждое слово и не дублировать существующие имена, aliases или понятия.
- Тема может быть широкой; создавать граф небольшими обоснованными срезами. Охват заявлять только в пределах выбранного среза.
- Категории — тематическая классификация по [rules/taxonomy.md](taxonomy.md), не замена предметных отношений. Новые категории создавать только при необходимости.
- Типизированные отношения должны соответствовать [rules/relations.md](relations.md). Одна прямая связь хранится в одном исходном Knowledge. Не добавлять выводимые, обратные или спорные отношения.
- При создании использовать первичные источники, если доступны. Для неоднозначных решений сохранить краткое обоснование в PR или, при сложном исследовании, в `reports/`.
- Новые узлы имеют `review_status: proposed`, Knowledge — `lifecycle: skeleton`. Независимое семантическое ревью отделено от генерации.
- Проверить граф [валидатором](validation.md); его PASS не подтверждает смысловую правильность связей.

Постановку можно передать обычным заданием. Отдельные `brief.md`, отчёты, идентификаторы партий и baseline создаются по необходимости, а не для каждого запуска. Исторические пилоты и их отчёты остаются без изменений.
