# Knowledge Graph Discovery — протокол

**Перед началом:** прочитай `AGENTS.md`, `rules/schema.md`, `rules/knowledge.md`, `rules/relations.md`, `rules/discovery.md`, `rules/validation.md`. Восстанови base/head ветки из GitHub, работай в отдельной ветке.

## Выбор режима

- `contract`: изменить только Harness/правила/проверки. Запрещено править предметные Knowledge/рёбра.
- `audit-nodes`: проверить **все узлы** в текущем scope, зафиксировать проверяемый источник и статус по каждому в реестре; спорные оставить `unresolved` до разумного поиска. После evidence — отдельная операция удаления/слияния с анализом ссылок.
- `audit-relations`: после node gate проверить каждый предикат и направленную тройку на подтверждённых Knowledge. Не создавать новый словарь по одному примеру.
- `discover`: после проверки источников добавить небольшой новый срез, при необходимости сразу доказанные рёбра.

## Для каждого режима

1. Определи конкретный вход и ожидаемый результат. Учитывай существующие ID, aliases и зависимости.
2. Не принимай внешний URL за evidence без чтения текста, даты/секции и проверки смысла имени.
3. Записывай только подтверждённые утверждения. Технический `review_status` не эквивалентен статусу `source_verified` в реестре.
4. Запусти static/tests, проверь дифф, опубликуй Draft PR с узким scope и ссылкой на доказательства.
5. В финале укажи `PASS`/`FAIL`/`NOT_RUN` **по отдельным воротам** (static, source, semantic, GUI).

Никаких скрытых массовых миграций, новых типов Category, дополнительных искусственных тематических узлов или архивных копий устаревших данных внутри Vault.
