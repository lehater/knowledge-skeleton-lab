# Knowledge Graph Discovery

1. Прочитай `AGENTS.md`, `rules/discovery.md` и относящиеся к задаче правила из `rules/`. Проверь существующий граф и `git status`. Работай в отдельной экспериментальной ветке; `main` не изменяй.
2. Ограничь широкую тему небольшим полезным срезом (по умолчанию до 8 **новых** Knowledge; явное задание может требовать больше). Не обещай полноту всей области.
3. Найди совпадения по имени, aliases и смыслу среди существующих Knowledge и категорий. Переиспользуй их вместо создания дублей.
4. Подтверди исходное название каждого нового Knowledge прочитанным источником и запиши URL в обязательное `sources`. Добавь минимальный каркас (YAML + H1, `proposed`, `skeleton`); рёбра опциональны — их разрешено добавлять сразу или позднее, независимо от узлов, только при доказанном предикате. Рубрикация статьи сама по себе не доказывает `part_of` или `broader`. ID создавай через `node tools/new-id.mjs`. Соблюдай `rules/schema.md`, `rules/relations.md` и `rules/taxonomy.md`.
5. Выполни `node tools/validate.mjs`, `node --test tools/validate.test.mjs`, `git diff --check`. При ошибках исправь результат или сообщи о блокировке.
6. Создай commit и Draft PR к экспериментальной ветке. В описании PR кратко укажи: тему и границы, что создано и переиспользовано, основания нетривиальных связей и источники, спорные вопросы, результаты проверок. Дополнительный отчёт нужен только при сложном исследовании.

**Передача:** ссылка на Draft PR — достаточный вход для независимого Semantic Review в отдельном чате. Проверяющий читает код, граф, правила и источники из GitHub, публикует замечания в PR; Codex исправляет их там же. До ревью не объявляй семантический PASS и не принимай `proposed` автоматически.

**Не делать:** новые предикаты/поля YAML, Canvas, массовое наполнение статей, дополнительные идентификаторы заданий и протоколы передачи.
