# Knowledge Graph Discovery

Перед работой прочитай `AGENTS.md`, `rules/schema.md`, `rules/knowledge.md`, `rules/relations.md`, `rules/discovery.md`; восстанови текущую ветку и Knowledge из GitHub.

## Режимы

- `discover` (**обычный**): подобрать источник, извлечь знание, переиспользовать или добавить Knowledge, указать URL и при необходимости направленные отношения.
- `contract` (**только при явном запросе**): менять правила/Skill/проверки без изменения предметных Knowledge.
- `correct` (**по конкретной проблеме**): исправить обнаруженное неверное знание, дубль или отношение после просмотра источника и затронутых ссылок.

## Порядок режима `discover`

1. Выбери наиболее надёжный для задачи стандарт, официальную документацию или первичную публикацию; прочитай нужный материал.
2. Найди в имеющемся графе тот же референт по названию, aliases и смыслу. Переиспользуй UUID либо создай новый.
3. Перенеси короткое утверждение в Knowledge (`lifecycle: enriched`) и URL в `sources`. Если есть только термин — `skeleton`.
4. Добавь только те отношения, которые действительно соответствуют источнику и предикатам `rules/relations.md`. Не связывай узлы искусственно.
5. Запусти `node tools/validate.mjs`, `node --test tools/validate.test.mjs` и `git diff --check`; сохрани небольшой результат в ветке и PR.

Не создавай отдельный evidence-реестр, баллы доверия, обязательный независимый review или новый онтологический тип. Нет необходимости аудировать весь существующий граф при каждом пополнении. Не меняй `main` и не выполняй merge без решения владельца.
