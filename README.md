# Knowledge Skeleton Lab

**Назначение:** единый Knowledge Graph (Markdown + YAML) для изучения программных систем в Obsidian. Источник истины — GitHub `main`; активные данные — `vault/`. Один доменный тип узла — `type: knowledge`.

## Текущее состояние

- **439 Knowledge / 638 направленных связей** после покрытия Harness Engineering (уровни 1–2), Python и Java (уровни 1–3) и добавления общих понятий программирования.
- **`kind` — необязательная природа референта Knowledge**, выбираемая по [словарю из 27 значений](rules/kinds.md). Не заменяет предметную тему, архитектурную ответственность или предикат отношения. Два значения (`requirement`, `event`) пока не используются.
- **8 типов отношений** определены в [rules/relations.md](rules/relations.md). `in_topic` описывает тематическую принадлежность, `part_of` — состав, `realizes` — реализацию абстракции. Выбирать их по `kind` автоматически запрещено.
- **Harness Engineering / ETCLOVG:** 1 корень, 7 направлений, 35 подразделов, 42 исходные тематические связи. Рубрикация источника не гарантирует предметную полноту.
- Схема и валидатор обеспечивают техническую целостность; **CI не подтверждает семантическую истинность всех карточек и ссылок**. Исторические аудиты доступны в `reports/`, но не вводят обязательный процесс ревью.

## Работа с графом в Obsidian

1. Открой `vault/` как Obsidian Vault.
2. Открой `views/knowledge.base`: таблица **Knowledge skeletons** содержит поле `kind`; представления **Components (kind)** и **Mechanisms (kind)** показывают два простых среза по природе сущностей. Это навигационные выборки, а не функциональные схемы.
3. Для тематической структуры используй `views/topics.base`; `views/topic-explorer.base` открывай в боковой панели рядом с активной Knowledge. В отдельной вкладке у неё может отсутствовать контекст `this`.
4. В K-Plex открой Knowledge `Harness Engineering` и выбери связь `in_topic`: ожидаются 7 направлений, затем 35 подразделов (7/4/5/3/5/5/6). Не интерпретируй тематические рёбра как `part_of`.
5. Для понимания функционирования читай ответственность, входы/выходы и сценарии в карточках; фильтр `kind` **не восстанавливает** автоматически поток данных, порядок вызовов и условия исполнения.

**Статус GUI:** представления `kind` подготовлены статически. Визуальное открытие новых Bases в Obsidian и ручная проверка результатов — **NOT_RUN**. Настройки локальных плагинов могут отсутствовать в Git (`vault/.obsidian/plugins/` игнорируется). Ранее подтверждённый пилот K-Plex для тематической рубрикации: [GUI-протокол](reports/harness-engineering/k-plex-etclovg-gui-validation-2026-11-01.md).
