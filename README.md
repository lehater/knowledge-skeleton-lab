# Knowledge Skeleton Lab

Репозиторий с отдельным **Obsidian Vault** в `vault/` и исследовательский стенд для построения агентом **каркаса предметной области**. На первом этапе предметные заметки содержат только YAML frontmatter и заголовок H1; объяснения добавляются после проверки графа.

**Концепция и полный сценарий:** [docs/concept.md](docs/concept.md) — назначение, модель, примеры построения графа, пользовательские запросы и критерии качества.

**Принятое решение о визуализации:** [ADR-001](docs/decisions/0001-graph-projections.md) — единый граф, Canvas по технологиям и фильтруемые представления по семействам отношений (фильтрация пока не реализована).

## Запуск через Codex в VS Code

Открой **корень Git-репозитория** как папку проекта VS Code (в отличие от Obsidian, где нужно открыть только `vault/`). В чате Codex дай команду:

> Выполни эксперимент из `prompts/first-discovery.md` по правилам `AGENTS.md`. Работай в отдельной экспериментальной ветке; `main` не меняй.

Перед началом создай ветку `git switch -c experiment/asynchronous-programming-pilot-001` из актуального `main`. Специальная команда CLI и отдельный `.agents/skills/` для первого запуска не нужны: повторно используемый Skill добавим только при подтверждённой пользе.

## Быстрый старт

1. Клонировать репозиторий и открыть **папку `vault/`** как Obsidian Vault (не корень репозитория).
2. Прочитать [AGENTS.md](AGENTS.md), [правила](rules/README.md), [задание пилота](experiments/asynchronous-programming/brief.md).
3. Передать агенту [готовое задание](prompts/first-discovery.md). Первый прогон — **не более 30 Knowledge**; пустой Vault специально не заполнен заготовками.
4. Запустить `node tools/validate.mjs` и `node --test tools/validate.test.mjs` (Node.js 22+).
5. Проверить граф и отчёт независимо, прежде чем принимать узлы и продолжать наполнение.

## Структура

- `vault/taxonomy/categories/` — категории, связанные ориентированным отношением `broader` (несколько родителей допустимы, циклы нет).
- `vault/knowledge/entries/` — узлы предметных знаний со ссылками `categories` и доказанными предметными отношениями.
- `rules/` — единственные локальные нормативные правила для агента.
- `vault/templates/` — минимальные шаблоны YAML + H1.
- `experiments/` — ограниченные постановки; `reports/` — проверочные свидетельства.
- `vault/views/` — Obsidian Bases для просмотра; необязательные графовые плагины могут читать те же YAML-связи.
- `tools/` — проверки целостности данных, без сторонних зависимостей.

## Границы

Это **эксперимент**, а не замена [knowledge-vault](https://github.com/lehater/knowledge-vault) или [Prep](https://github.com/lehater/prep). Ни существующие Knowledge, ни их идентичность сюда автоматически не мигрируют. Модель классификатора здесь **кандидатная** и должна пройти предметное ревью. Количество узлов **не** доказывает полноту знаний.

**Граница:** в Obsidian открывается только `vault/`; `AGENTS.md`, `rules/`, `tools/`, `prompts/`, `reports/` и `.github/` остаются за пределами Obsidian. Агент запускается из корня репозитория.

**Хранение:** смысловая принадлежность задаётся графом, а не папками. Все ссылки в YAML — quoted wikilinks на полные vault-relative пути без `.md`. `AGENTS.md` — указатель на правила, а не место дублирования семантической модели.
