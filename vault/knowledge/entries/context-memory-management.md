# Context & Memory Management

Управление контекстом и памятью определяет, какая информация доступна модели на текущем шаге и что сохраняется для продолжения работы. Входы — инструкции, история сообщений, определения и результаты инструментов, внешние данные; выход — отобранный контекст следующего вызова и обновлённое сохраняемое состояние.

Для активного окна важны релевантность и ограниченный бюджет токенов. Для длинных задач применяют сжатие истории, внешние заметки и разделение контекстов. Persistence имеет разные области: в LangGraph checkpointer сохраняет состояние конкретного thread, store — данные между threads. Их содержимое требуется явно возвращать в контекст модели; наличие записи в хранилище не означает её присутствие в запросе.

Слой отвечает за доступность и связность информации, но не за выбор переходов workflow или оценку истинности каждого сохранённого факта. Увеличение окна не устраняет ухудшение работы с длинным контекстом, а сохранение состояния само по себе не обеспечивает корректность продолжения.
