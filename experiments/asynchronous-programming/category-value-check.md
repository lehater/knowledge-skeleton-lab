# Pilot 001 — проверка полезности категорий

**Статус:** представление подготовлено, ручная проверка Obsidian — **NOT_RUN**.
**Вход:** неизменённый граф Pilot 001 (19 Knowledge и 5 Category).
**Одна гипотеза:** категория помогает найти нужные знания по предметной теме быстрее, чем просмотр плоского списка из 19 файлов.
**Граница:** тестируется только **прямая принадлежность** `categories`, без фасетов, новых рёбер и наследования через `broader`.

## Подготовленный результат

Представление: `vault/views/category-explorer.base`. Два режима **одного** Base:

- **По категориям** — список Knowledge, сгруппированный по человекочитаемому `name` категории. Заголовок группы вычисляется из ссылки `categories[0]`: технические пути остаются в YAML, но в заголовках группы должны появиться понятные имена. Колонка «Перейти к категории» — обычная ссылка.
- **Текущая категория** — динамический фильтр по `this.file`. Режим предназначен для закрепления Base **в боковой панели**: если в основной области открыта заметка категории, показываются знания с прямой ссылкой на неё.

Ни один `Knowledge` и ни одна `Category` не изменены. Для первого пилота у каждого Knowledge ровно **одна** прямая категория. Формула `categories[0]` сознательно показывает только первую; сценарий многокатегорийности требует отдельного решения.

## Ожидаемая картина (подсчитано по YAML, не результат GUI)

| Категория | Прямых Knowledge |
| --- | ---: |
| Asynchronous Execution | 9 |
| Asynchronous Lifecycle | 4 |
| Asynchronous Flow Control | 2 |
| Asynchronous Programming | 2 |
| Concurrent Programming | 2 |
| **Всего** | **19** |

**Важно:** в более широкой `Asynchronous Programming` непосредственно находятся **2** Knowledge; знания дочерних категорий сюда автоматически не наследуются в этом Base. Дерево `broader` — следующий самостоятельный эффект, если пользователь подтвердит полезность прямой группировки.

## Приёмочный сценарий в Obsidian

1. Синхронизировать экспериментальную ветку; открыть **только папку `vault/`** как Obsidian Vault.
2. Открыть `views/category-explorer.base`, выбрать режим **«По категориям»**.
3. Проверить: есть **5 групп и 19 строк**; названия групп без префикса `taxonomy/categories/`; развернуть `Asynchronous Execution` — **9** знаний.
4. Нажать на `Coroutine Suspension and Resumption` — должна открыться соответствующая заметка. Нажать ссылку категории — должна открыться соответствующая Category.
5. Переместить Base в боковую панель и переключить на **«Текущая категория»**; в основной области открыть `taxonomy/categories/asynchronous-execution.md` — ожидаются **9** знаний; затем `asynchronous-lifecycle.md` — **4**.
6. Опционально: открыть **Local Graph** для `asynchronous-execution.md` с глубиной 1 и посмотреть прямое окружение категории. Встроенный Graph показывает ссылки, а не типы отношений.
7. Сравнить с навигацией через плоский `views/knowledge.base`: удалось ли **быстро выбрать тему и найти нужную заметку** без поиска по всем файлам?

## Доказательства и решение

| Критерий | Ожидание | Проверено |
| --- | --- | --- |
| Группировка | 5 групп / 19 записей, без служебных путей в заголовках | NOT_RUN GUI |
| Drill-down | 9 знаний в Execution, 4 в Lifecycle | NOT_RUN GUI |
| Навигация | Открывается Knowledge и Category из Base | NOT_RUN GUI |
| Понятность | Пользователь может объяснить, почему знание в категории | NOT_RUN |
| Полезность | Навигация заметно удобнее плоского списка | NOT_RUN |

**Решение после теста:**
- Если группировка полезна и работает — фиксировать `VALUE_CONFIRMED` в отчёте и только затем рассматривать следующий эффект (например, наследование `broader`).
- Если не работает/неудобно — `BLOCKED`, исправить только представление, без изменений модели.
- Если категории не помогают выбирать знания по теме — `VALUE_NOT_CONFIRMED`; пересмотреть сами категории прежде, чем расширять онтологию.

## Технические ограничения

Используются только встроенные Bases; плагины не требуются. Синтаксис формул и `this.file` основан на официальной документации:
- https://obsidian.md/help/bases/syntax
- https://obsidian.md/help/bases/functions
- https://obsidian.md/help/bases/views

Из Git/CI **нельзя доказать**, что конкретная версия Obsidian корректно отображает Base: требуется реальная проверка GUI. Если формулы не распознаются, зафиксировать фактическую ошибку, а не объявлять тест пройденным.
