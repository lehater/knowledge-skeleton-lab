# ADR-001 — Один Knowledge Graph, несколько проекций

**Статус:** принято направление проектирования.  
**Актуализировано:** 2026-11-01, в рамках очистки Harness.

## Контекст

Нужно изучать предметную область с разных точек зрения, не дублируя Knowledge в каждой визуализации. Одновременно нельзя считать компоновку Canvas или K-Plex предметным фактом.

## Решение

1. **Каноническая модель:** только `vault/knowledge/entries/*.md` и типизированные YAML-рёбра. Словарь рёбер определён в [rules/relations.md](../../rules/relations.md).
2. **Canvas:** сохранённая читаемая схема выбранного среза. Линии и подписи обязаны соответствовать подтверждённым фактам YAML; Canvas не является хранилищем новых предметных рёбер.
3. **K-Plex/Graph:** интерактивное исследование соседства Knowledge с линзами по предикатам. Фильтр меняет видимость, не онтологию.
4. **Bases:** таблицы и запросы к тем же Knowledge. Не новые сущности и не альтернативный источник истины.
5. **Scope:** параметр просмотра (`root + predicates + direction + depth`); дополнительный тип Knowledge или Scope-узел не нужен.

## Проверенный пилот

Для авторской рубрикации ETCLOVG в K-Plex владелец подтвердил семь направлений, 35 подразделов и переход фокуса. [GUI-протокол](../../reports/harness-engineering/k-plex-etclovg-gui-validation-2026-11-01.md). Проверено отображение, **не** предметная полнота.

## Ограничения

Генерация Canvas из YAML, рекурсивные Scope-вычисления и независимый UI-прогон не реализованы/не подтверждены. Учебные `python-asyncio*.canvas`, случайно сохранённый Canvas среди Knowledge, специализированная `python-asyncio-relations.base` и прежние задания пилотов **удалены из рабочего дерева на Stage 3**. Это удаление представлений, не удаление доказанных Knowledge и рёбер. Повторная ручная проверка K-Plex после очистки — **NOT_RUN** до подтверждения владельцем.
